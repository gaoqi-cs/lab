# 校园实验室安全巡检助手

该项目包含 FastAPI 后端和微信小程序前端，提供实验室安全场景图片判别、自定义安全类别训练、安全规程资料入库与流式安全操作问答。

- 后端依赖：已按 `requirements.txt` 安装，并补充 `llama-cpp-python` CPU 运行时
- VS Code：已配置 Python 解释器、调试启动项和后端任务
- 微信开发者工具：已检测到本机安装版本 `2.01.2510290`
- 小程序接口：默认指向本机 `http://127.0.0.1:8001`

## 前端界面

小程序已按“校园实验室安全巡检助手”重构为科技蓝科研工具风，包含：首页、图像隐患识别、场景样本训练、安全规程资料库和实验室安全问答五个页面。视觉规范与色彩说明见 [DESIGN.md](DESIGN.md)。

## 在 VS Code 启动后端

1. 在 VS Code 中打开 `D:\桌面\实训代码`。
2. 按 `F5`，选择“启动实验室安全巡检助手后端”。
3. 浏览器访问 `http://127.0.0.1:8001/docs` 查看接口文档，或访问 `/health` 检查服务状态。

## 打开小程序

用微信开发者工具导入 `D:\桌面\实训代码\miniprogram`，选择“小程序”项目类型后即可编译预览。真机联调时，将 `miniprogram/app.js` 中的 `apiBase` 改为电脑局域网 IP，例如 `http://192.168.1.10:8001`，并确保防火墙允许 8001 端口。

如果导入后页面主体全黑，点击顶部“编译”重新加载。项目已改为使用原生导航栏和 `WebView` 渲染模式，避免 `Skyline` 自定义导航在部分开发者工具版本中的渲染兼容问题。

若调试器提示 `knowledge.wxml get tag end without start`，请先同步最新代码后重新编译；该标签层级问题已修复。

## 模型资源

后端可在缺少模型时启动，但分类、知识库和问答功能需要对应资源。模型路径及默认 CPU/GPU 策略在 `app/config/config.py` 中定义；请将已有模型文件放到 `data/models` 下的相应目录。

## 已实现的业务闭环

- 识别结果可保存为本地巡检记录，首页展示最近一条记录；记录不保存巡检原图。
- 已成功入库的规程资料会在重启后继续显示，支持按文件名搜索。
- 未下载嵌入模型时，资料仍会写入本地关键词检索库；问答会基于命中资料调用 DeepSeek 并标注来源。
- 训练页可真实请求停止任务，并会根据接口结果更新状态。
- 巡检记录和资料目录保存于 `data/json`，属于本地演示数据；生产环境应改用受控数据库、账号权限和审计策略。

### 图像训练样本要求

首次训练时勾选“重新训练时清空原有训练样本”，上传第一个类别后系统只会保存样本并提示继续添加。每批最多上传 9 张图片，可重复分批保存；后续批次会追加保存，不会覆盖之前的图片。至少准备两个类别，且每个类别至少需要 2 张有效图片，建议 30 张以上。页面会显示已收集的案例名称和图片数量，确认样本准备完成后，再点击“准备完成，开始训练”。训练与验证集会按类别划分，避免出现空验证集。

## DeepSeek 问答配置

问答链路会优先检索本地安全规程；没有命中时，已配置的 DeepSeek 会作为云端问答补充。未配置时仍尝试使用本地 GGUF 模型。

1. 打开项目根目录的 `.env`，只填写 `DEEPSEEK_API_KEY=你的密钥`。
2. 保持 `DEEPSEEK_BASE_URL=https://api.deepseek.com` 和 `DEEPSEEK_MODEL=deepseek-v4-flash`，除非你有明确的服务端或模型切换需求。
3. 重启后端；启动日志只会显示模型名称，不会输出密钥。

`deepseek-v4-flash` 在该接口下会先使用较多推理 token。后端会自动将它的单次最小输出预算提升到 `4096`，防止返回空回答；这会提高单次调用的最大 token 消耗上限。

`.env.example` 是可共享的配置模板，`.env` 已被忽略，不要将真实密钥写入代码、README 或聊天记录。

## 本次功能修复

- 修复知识库命中后仍调用 DeepSeek 的问题：关键词或向量检索命中本地资料时，问答直接返回资料片段并附来源；只有未命中时才调用 DeepSeek 兜底。
- 改进关键词检索：中文自然问句会拆分为二到四字片段，不再要求整句与文档原文完全相同。
- 整理聊天接口、RAG 服务和小程序页面的 WXML/WXSS 排版，补充必要注释和字段校验。
- 优化本地资料回答精度：问题开头的对象或场景优先匹配，仅返回最相关的一个资料片段（最多 800 字）；弱匹配不会冒充本地答案，会转入模型兜底。

## 训练界面与识别修复

- 修复分批上传时文件名可能重复、旧图片被覆盖的问题；每批样本现在只保存，不会因为上传第二个类别而自动训练。
- 新增训练数据概览接口，训练页显示每个案例名称和当前图片数量；用户点击开始训练后才提交训练任务。
- 修复训练集和验证集共用图片变换的问题，保证训练增强不会覆盖验证预处理，有助于得到更可靠的验证结果。
- 训练案例列表支持删除；确认后会删除该案例的全部已保存样本，训练进行中不允许删除。
- 若小程序提示 `ERR_CONNECTION_REFUSED`，请先启动根目录配置的后端，并确认 `http://127.0.0.1:8001/health` 可访问；真机调试需将 `apiBase` 改为电脑局域网 IP。
- 修复余弦分类器类别权重归一化维度错误，该问题会造成训练后大量图片被判为同一类别。修复代码后需要重新点击“准备完成，开始训练”生成新模型。
- 训练时保留预训练骨干的大部分参数，仅微调 ResNet 最后特征块和分类头，避免只训练分类头导致小样本场景下分类塌缩。
